# Gradfolio-ի թեստավորման թարմացված հաշվետվություն

**Ամսաթիվ՝ 2026-10-17։** Frontend՝ `9d6b214` և տեղական շտկումներ։ API՝ `f131ba6`։ Նախորդ ամբողջական վազքը՝ 2026-10-16, լրացուցիչ ստուգումները՝ 2026-10-17։

## Ամփոփ արդյունք

Նախկինում բաց թողնված 55 signed-in browser դեպքերն այժմ կատարվել են տեղական իրական frontend–API–MySQL շղթայով։ 64 դեպքի վազքն ամբողջությամբ անցել է՝ առանց բաց թողնման և կրկնափորձի։ Այն ներառում է այդ 55 դեպքը, 7 անանուն դեպք և 2 նոր regression ստուգում։ Ստուգվել են անգլերեն, ռուսերեն և հայերեն տարբերակները, բաց և մուգ թեմաները, 390 և 1440 px էկրանները, հասանելիությունն ու ստեղնաշարով կառավարումը։

Նույնականացումը կատարվել է նախագծի գործող թեստային issuer-ով և Auth0 SDK-ի թեստային session cookie-ներով։ API-ն իրականում ստուգել է ստորագրված token-ները, իսկ տվյալները պահպանվել են մեկուսացված MySQL 8.4-ում։ Սա հաստատում է մուտքից հետո հասանելի գործառույթները, բայց չի հաստատում իրական Auth0 կամ social login ծառայությունների կարգավորումները։

Հաստատված խնդիրների ընդհանուր թիվը՝ **4**։ Մեկը հանրային էջի նավիգացիայի խնդիր է, մյուս երեքը՝ lint/browser թեստավորման խնդիրներ։ Բոլորի համար պատրաստված են տեղական շտկումներ։ Դրանք դեռ չեն commit/push/deploy արվել։

## Հաստատված խնդիրներ և դրանց լուծումները

### 1 Հանրային նախագծից հետ գնալը պահանջում է մուտք

**Խնդիր․** անանուն այցելուի «Back to Projects» հղումը տանում էր պաշտպանված `/projects` էջ, ապա՝ Auth0 մուտքի էջ։ Դա խախտում էր հանրային նախագծերի դիտման ուղին։

**Լուծում․** սեփականատիրոջ համար պահպանվել է `/projects`, մյուս այցելուների համար ընտրվել է `/browse/projects`։ Ավելացվել են երկու regression թեստ։ Տեղական շտկումը ստուգված է։ Հրապարակված կայքում շտկումը կհաստատվի միայն նոր deploy-ից հետո։ [GitHub #113](https://github.com/Levon0Asatryan/gradfolio/issues/113)։

### 2 Playwright-ի հաշվետվությունից հետո lint-ը խափանվում է

**Խնդիր․** ESLint-ը կարդում էր գեներացված Playwright trace ֆայլերը և ավարտվում `RangeError: Invalid string length` սխալով։

**Լուծում․** `playwright-report` և `test-results` պանակները հանվել են ESLint-ի ստուգումից։ Հաշվետվության առկայությամբ lint-ի, coverage-ի և build-ի կրկնակի վազքն անցել է։ [GitHub #114](https://github.com/Levon0Asatryan/gradfolio/issues/114)։

### 3 Signed-in թեստերը սխալ են հաշվառում Vercel-ի տեղական 404 պատասխանները

**Խնդիր․** dashboard, notifications, team և teams թեստերը ձախողվում էին երկու վիճակագրական script-ի տեղական 404 պատասխանների պատճառով։ Առանձին browser probe-ը հաստատել է, որ դրանք `/_vercel/insights/script.js` և `/_vercel/speed-insights/script.js` հասցեներն էին։

**Լուծում․** ավելացվել է ընդհանուր console/network ստուգիչ։ Այն հաշվի է առնում Vercel-ին հատուկ script-ները և Next-ի չեղարկված RSC prefetch-ները, իսկ իրական HTTP, network և չբռնված JavaScript սխալները շարունակում է գրանցել։ Ավելացված regression ստուգումները ներառում են դիտավորյալ HTTP 500 և JavaScript exception։ Շտկումից հետո 64 դեպքի վազքն անցել է։ [GitHub #115](https://github.com/Levon0Asatryan/gradfolio/issues/115)։

### 4 Ծանուցման հաշվիչի թեստը ստուգում է թաքցված ֆոնային կոճակը

**Խնդիր․** ծանուցումը կարդալուց հետո թեստը ստուգում էր ֆոնային զանգակի accessible name-ը, երբ dialog-ը դեռ բաց էր։ MUI-ն այդ պահին ճիշտ կերպով ֆոնը հանում է accessibility tree-ից, ուստի անունը թեստի համար դատարկ էր։ API-ի հաշվիչն արդեն ճիշտ նվազել էր։

**Լուծում․** հաշվիչի API փոփոխությունը հաստատելուց հետո թեստը փակում է dialog-ը և ստուգում զանգակի անունը։ Կրկնակի վազքում դեպքն անցել է։ Սա թեստի խնդիր էր, ոչ թե հաստատված ծանուցումների հաշվիչի սխալ։ [GitHub #116](https://github.com/Levon0Asatryan/gradfolio/issues/116)։

## Կախվածություններ և միջավայր

Ամբողջ dependency tree-ի audit-ում frontend-ն ունի 5 high, API-ն՝ 3 high նշում։ Դրանք կապված են `braces`-ի stack exhaustion advisory-ի և այն օգտագործող զարգացման գործիքների հետ (`micromatch`, `fast-glob`, `knip`, `kysely-codegen`, Next ESLint plugin)։ Դրանք 8 անկախ application vulnerability չեն։ Երկու նախագծերի runtime-only audit-ն այս վազքում տվել է 0 advisory։

Հաջորդ քայլը զարգացման գործիքների համապատասխան տարբերակների թարմացումն ու verify-ի կրկնումն է։ `npm audit fix --force`-ի առաջարկած major փոփոխությունները կամ հին տարբերակների վերադարձը չեն կիրառվել առանց համատեղելիության ստուգման։ Աղբյուր՝ [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) և պահված npm audit հաշվետվությունները։

Windows-ի սկզբնական վազքերի POSIX fixture-ների և locale-ի սահմանափակումների պատճառով ամբողջական ավտոմատ արդյունքների հիմքը Linux միջավայրն է։ Միանգամյա հայերեն accessibility timeout-ը նախկին վազքում անցել էր կրկնափորձով․ նոր signed-in վազքի 64 դեպքերն անցել են առանց կրկնափորձի։

Հրապարակված կայքի անանուն ուղիները և API readiness-ը ստուգվել են 2026-10-16-ին։ Այսօրվա տեղական արդյունքները չեն համարվում հրապարակված կայքի նոր ստուգում կամ նոր deploy։

## Ինչ պետք է անել հիմա

1. Review/commit անել տեղական շտկումները և ներառել դրանք CI-ում։
2. Հրապարակել frontend-ի շտկումը և production-ում կրկնել #113-ի հանրային նավիգացիան։
3. Ավարտել M7/M8-ի պարտադիր աշխատանքը և արտաքին Auth0/GitHub/GCS ստուգումները։
4. Վերջնական release ընդունումը կատարել այդ պայմանների փակումից հետո։ Այս հաշվետվությունը կատարված թեստերի վերջնական արձանագրությունն է, ոչ ամբողջ v1-ի անվերապահ release հաստատում։
